# 발표 덱의 디자인 역할

## 세 가지 역할

1. **설명 장표**: 숫자, 비교, 도해와 실물을 읽는다. 내용에 따라 구도를 고르고 제목·부제·본문을 매번 같은 틀에 넣지 않는다.
2. **진행 장면**: 발표자가 클릭할 때 대상과 초점이 바뀐다. 다음 이야기는 자동으로 공개하지 않는다.
3. **이벤트 장표**: 표지와 Factory 연속 장면에서 공간과 카메라 이동을 쓴다.

## 디자인 리뷰 반영

사용자가 만족한 1·2·5번의 구성은 유지한다. 3·4·7·8·12~17번은 다시 구성하고, 6·9~11번은 읽는 순서와 문장을 정리했다. 이후 승인된 18~22번 영상은 유지하고, 26번 뒤에 악용 서사 7장을 추가해 전체 37장이 됐다(2026-09-23 재구성으로 8장, 전체 38장). 기존 화면 ID와 단계 수는 유지한다.

- 3번은 강의 제작 요청과 실제 영상 캡처를 잇는다. 2번 고양이 사진의 DOM은 역방향 이동을 위해 유지하되 3번에서는 숨긴다.
- 4번은 표지의 배경을 반복하지 않고, 2031년에 AI에게 맡기게 될 일을 묻는다.
- 6번은 HTML 요청 비중을 같은 길이 척도의 막대와 숫자로 표시한다. 관측 날짜와 범위를 화면에 남긴다.
- 7번은 사람 확인과 에이전트에 제공하는 기능을 구분한다. 8번은 같은 구매 조건 아래 가격 차이, 선택, 판매자의 가격 전략 질문을 차례로 공개한다.
- 9~11번은 하나의 3D 사건 재구성 공간(three.js)을 세 장 동안 유지한다. 유리 샌드박스 4개, 공용 서버, 방화벽, 벽 밖의 외부 인터넷과 Hugging Face를 같은 좌표계에 두고, 단계마다 카메라와 초점만 옮긴다. 대본과 제목·날짜·본문은 그대로 두고, 화면 아래 타임라인으로 5월 훈련과 7월 평가가 다른 구간임을 표시한다. 카메라 샷은 좌표를 직접 적지 않고, 단계별로 보여야 할 대상이 제목과 본문을 피한 화면 영역에 들어오도록 계산한다. 색은 파랑=실행과 서버, 청록=7월의 실행 역할, 호박색=평가 환경 밖으로 나간 연결이다.
- 12번은 한 장 안에서 스크롤하는 홈페이지다. 해 질 녘 빈 대지의 평면선 위로 집의 부품이 위와 좌우에서 날아와 조립되고, 카메라가 물러나며 개발자 구역(3조 달러)과 7개 직군의 도시(18.6조 달러+)가 서고, 도시 위로 판단의 빛이 오간 뒤 다시 집으로 내려온다. 영상은 Blender(Cycles)로 렌더하고 스크롤 위치가 프레임을 고른다. 글은 왼쪽 단에 두고, 집과 도시는 오른쪽에 오도록 카메라를 잡는다(`render-house-scroll.py --mode layout`). 정지 지점에서는 카메라와 부품이 멈춰 있어 흐림이 없다(`--mode verify`). 청사진 선은 첫 화면과 도시 구간에서 두 번 쓰여 "설계가 실물이 된다"를 반복한다.
- 13~16번은 개인의 고민, 강의 제작, 혼자 쓰는 도구의 조건, 맡기고 검토하는 순서로 이어진다. Agent OS와 Factory의 전체 연결은 구상임을 표시한다.
- 17번은 실제 강의 캡처, 새로 생성한 새 이미지, 음악 파형을 연출한 장면으로 다음 영상의 결과물을 미리 보여준다.

### 2026-09-23 리뷰 반영: 2~3, 7~8, 13~17번

사용자 평가에서 9~12번(three.js 공간, Blender 스크롤 영상)과 18~22번(Blender 영상)이 가장 높았고, 평면 PPT 구도(제목·표·세 칸)인 7·8·14~16번이 가장 낮았다. 그래서 낮게 평가된 장표를 같은 언어, 즉 하나의 공간을 여러 장 동안 유지하고 발표자의 입력마다 카메라와 상태만 옮기는 방식으로 다시 만들었다.

- 2~3번: "사진 한 장 → 단어 하나"와 "요청 한 문장 → 강의 한 편"을 같은 공간에서 대비한다. 사진 원본이 550×378이라 화면 전체로 키우지 않고, 저해상도를 화소 부조로 바꾸는 연출에 썼다.
- 7~8번: 7번의 판매처 화면이 그대로 8번의 판매처 A가 된다. 사람 확인은 그대로 두고, 사이트가 따로 내놓은 기능을 에이전트가 부르는 것으로 WebMCP를 보여준다.
- 13번: 12번의 마지막 집 이미지에서 이어져 "도시 → 집 한 채 → 한 사람"으로 내려온다.
- 14번: 실제 제작 기록(대본·파형·단어 정렬·프레임)을 편집기 타임라인처럼 놓아, 도식 대신 실물로 설명한다.
- 15~16번: 금색 점(저)을 한 공간에 두고, 15번에서는 조건이 느슨해지고 16번에서는 그 점을 둘러싼 흐름의 고리가 드러난다. 구상과 개발 중을 화면에 구분한다.
- 17번: 18번 Blender 갤러리와 같은 배치·재질로 Factory의 입구를 만든다.

1·4·5·6번은 "나쁘지 않음"으로 평가돼 이번에는 바꾸지 않았다.

화면은 짧고 구체적인 문장으로 쓴다. 설명이 필요한 이유는 대본에 둔다. ‘생산 능력으로 연결’, ‘기반을 쌓는다’처럼 대상과 행동이 흐려지는 표현은 실제로 하는 일로 풀어쓴다.

## 구현과 확인

기존 공통 스타일은 `presentation.css`에 둔다. 장표별 스타일은 해당 폴더(`opening/`, `agent-web/`, `personal/`)와 `opening-revision.css`, `story-revision.css`로 범위를 제한한다. 18~22번은 장면마다 다른 전환과 최종 구도를 가진 Blender 영상으로 구성했다. 23번 이후 미디어 재생은 유지한다.

`npm run check:keynote`는 전체 장표의 모든 단계, 화면·대본 연결, 사진 DOM 유지와 역방향 이동, 도해 연결선, Factory 영상 재생과 마지막 화면 유지, 미디어 재생, 발표자 동기화를 확인한다. 픽셀 완전 일치 이미지를 회귀 기준으로 고정하지 않는다. 실제 화면의 문장과 정보 위계는 렌더를 보고 따로 확인한다.

## Factory의 촬영과 편집

18~22번은 동일한 공간을 옆으로 이동하는 공통 카메라를 사용하지 않는다. Blender에서 장면마다 촬영과 전환을 만들고, 브라우저는 발표자의 클릭에 맞춰 해당 영상을 재생한 뒤 마지막 화면을 유지한다.

- 18→19: 중앙 화면을 통과해 음성 파형 사이로 들어가고, 실제 강의 화면 앞에 도착한다.
- 19→20: 강의 프레임의 위치와 방향을 이미지 프레임에 맞춘 매치 컷으로 바꾸고, 이미지의 세부를 지나 전체 결과를 보여준다.
- 20→21: 화면을 덮는 물체로 컷을 가린 뒤, 낮은 앵글에서 원반의 위쪽으로 시점을 바꾼다.
- 21→22: 원반 중앙의 원형 구멍을 통과한 뒤, 카메라가 올라가며 여러 결과물을 드러낸다.

최종 구도도 각각 다르다. 강의는 큰 화면, 이미지는 전체 그림, 음악은 탑뷰, 마지막은 여러 결과물이 놓인 공간이다. 문장은 장면이 멈춘 뒤 짧은 자막처럼 표시한다. 이전의 왼쪽 설명·오른쪽 오브젝트 구도를 반복하지 않는다.

Blender 원본과 최종 영상은 `tools/render-factory-film.py`와 `public/factory-film/`에서 관리한다. 실제 강의 영상과 새 생성 이미지를 텍스처로 사용하고, 음악 파형은 실제 후보에서 가져온다. 영상 자체를 생성 모델의 출력이라고 표시하지 않는다.

실물 결과물은 작업의 완료 시각순으로 목록을 확인하고 최신 2D·3D 파일을 실제로 열어 비교한다. 작업 제목이나 오래된 입력 이미지만 보고 선택하지 않는다. 최신 결과가 장면에 맞지 않으면 현재 엔진으로 새 작업을 생성한다. 시스템 초기의 불안정한 출력은 소개용 대표 결과로 재사용하지 않는다.

검수에서는 경계 전후의 연속 프레임을 비교해 네 전환이 실제로 다르게 보이는지 확인한다. 재생·마지막 화면 유지·역방향 이동·모션 정지·발표자 동기화 검사를 별도로 수행한다.

## 악용 서사의 전환

27~34번은 설명보다 체감을 목표로 한다(2026-09-23 리뷰: "살짝 안 무서워"). 초록 해커 화면 대신 어두운 방과 붉은색을 쓰고, 빨강은 합성·거짓에만 쓴다.

- 27번: 무서움의 출발점은 사실이다. 청중이 23번에서 들은 제 목소리의 한 문장을 다시 보여주고, 그 문장을 녹음한 적이 없다는 것, 제 목소리를 흉내 내는 데 든 실제 기록(12.3분·35.3초·약 67MB)을 보여준다.
- 31·32·34번: 도식 대신 피해자의 시점이다. 새벽의 협탁 위 휴대전화 한 대가 세 장면의 무대이고, 전화가 연결되면 카메라가 휴대전화로 다가가 자막을 읽게 한다. 같은 휴대전화에서 확인하는 방법으로 끝나 긴장을 푼다.
- 30번: 네 개의 벽이 무너지면 지평선의 붉은 빛 앞으로 검은 군중이 다가온다. 15번에서 사라졌던 "많은 사용자"가 되돌아오는 대구다.
- 33번: 사본이 두 배씩 늘어 화면을 채운다. 원본에 "삭제" 도장이 찍혀도 사본은 남는다.

반복 점멸은 쓰지 않는다. 진동음은 발표자가 A를 눌렀을 때만 난다. M 또는 모션 줄이기 설정에서는 각 단계의 마지막 상태를 보여준다.

현재의 수고는 발표자 자신의 통합 제작 과정에 대한 경험이다. 일반인은 아직 음성을 복제할 수 없다는 주장으로 확대하지 않는다. 다음 모델의 발전은 가정으로 표시하고, 이미 보고된 사칭·합성물 피해는 출처로 구분한다. 구체적인 외도 음성 상황은 가상 사례다.

## 마무리: 같은 집의 아침

35~38번은 악용 서사의 "새벽 2시 47분" 뒤에 오는 답이다(2026-09-23 리뷰: "싹 변경"). 새 배경을 만들지 않고 12~13번의 집을 시간대만 바꿔 다시 렌더해, 밤 → 푸른 새벽 → 아침으로 이어지게 했다. 네 장은 한 묶음이라 배경이 끊기지 않고, 38번에서만 흐림이 걷히며 선명한 아침이 된다.

- 35번: 주장("모델이 바뀌어도 작업은 남는다")을 그림으로 보인다. 위에서는 모델이 지나가고, 아래에서는 실제 판단 기록·작업 방식·결과물이 쌓인다. 미래의 모델 이름은 만들지 않고 "다음 모델·가정"으로 둔다.
- 36번: "과정도 공개한다"는 말 대신 실제로 잘 안됐던 기록을 보여준다. 슬롭이라고 말하는 청중에게 가장 설득력 있는 것은 성공 사례보다 무엇을 버렸는지의 기록이라고 판단했다.
- 37번: 12번의 청사진 선을 이어 쓴 설계도. 실선(개발 중)과 점선(구상)의 구분은 16번과 같다.
- 38번: 질문을 두 낱말(만들기·맡기기)로 줄였다. 초점 틀이 옮겨 가면 아침빛의 색도 금색·푸른색으로 바뀐다.

진행은 발표자의 입력에 따른다. M 또는 운영체제의 모션 줄이기 설정에서는 움직임 없이 해당 단계의 결과를 표시한다. 출처와 사실의 범위는 `deck/FACT-CHECK.md`, 배경 생성 기록은 `docs/abuse-art.md`에 둔다.
