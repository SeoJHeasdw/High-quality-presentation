# 발표 덱의 디자인 역할

## 세 가지 역할

1. **설명 장표**: 비교, 표, 도해, 근거를 읽는 PPT. 제목·본문의 위계와 정렬을 안정적으로 유지한다.
2. **진행 장면**: 발표자가 클릭할 때 같은 대상의 자리·크기·강조가 바뀐다. 자동으로 다음 이야기를 공개하지 않는다.
3. **이벤트 장표**: 이야기 전환점에 집중하는 강한 영상미. 4번과 Factory 연속 장면이 해당한다.

4번의 모양이나 배경을 일반 설명 장표의 기본 템플릿으로 삼지 않는다.
이벤트의 밀도와 움직임은 설명 장표와 다르게 둔다.

## 현재 구현

- 설명 장표의 글꼴은 Pretendard를 유지한다. 제목·본문의 굵기, 자간, 대비를 구분하고 비교 영역은 선과 정렬로 연결한다.
- 일반 장표의 보정은 `presentation.css`의 `.kn-brief` 범위에 한정한다. 이벤트 스타일에 전파하지 않는다.
- 2~3번은 같은 사진 DOM을 유지한다. 중앙 질문, 왼쪽 이동과 답, 현재의 부탁, 작업 구성의 네 큐를 방향키로 진행한다.
- 8번은 가상의 판매처 표, 조건에 따른 선택, 가격 전략 질문으로 진행한다. 가격과 조건은 실제 시장 데이터가 아니다.
- 9~11번의 도해는 방, 게시판, 외부 시스템을 하나의 좌표계에 놓는다. 움직이는 선은 실제 연결 경로를 따른다.
- 4번과 엔진 연속 장면은 이번 보정에서 변경하지 않았다.

## 확인

정지 화면만 확인하지 않는다. 2~3번의 중간 이동과 역방향 이동, 사진 유지 여부,
9~11번의 연결선 시작·끝과 실제 노드 포트를 확인한다.
발표자가 말을 멈춰도 다음 큐가 자동으로 나오지 않아야 한다.

`npm run check:keynote`는 전체 장표 검수와 위 동작 검사를 수행한다.
픽셀 완전 일치 이미지를 회귀 기준으로 고정하지 않는다.
