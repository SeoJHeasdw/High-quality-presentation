# JAVIS / 제가 살아가려는 방식

Technology Expert Lab 팀과 나누는 30년 생존 실험. 57장, 137개 발표 단계로 구성한 16:9 브라우저 발표다.
일반 설명은 숫자·비교·도해와 실제 결과물로, 대상 이동은 발표자가 누르는 큐로 표현한다. 표지와 Factory 연속 장면에는 공간 연출을 쓴다.

## 실행

```bash
npm install
npm run dev
```

- [발표 화면](http://localhost:5180/#keynote)
- [발표자 대본](http://localhost:5180/#keynote/present)
- [이전 기술 강의](http://localhost:5180/#course)

`→` / `Space`: 다음 단계, `←`: 이전 단계, `숫자 + Enter`: 장표 이동.
`F`: 전체화면 켜기/끄기, `Esc`: 전체화면 종료, `H`: 조작 바 켜기/끄기, `M`: 모션 정지, `R`: 현재 장면 재시작.
발표자 창은 같은 브라우저에서 열어야 동기화된다.
글자 단축키(F·H·M·R·W·P·A 등)는 한글 입력 상태에서도 동작한다. 글자 대신 자판 위치(`e.code`)로 읽는다(`src/components/keys.ts`).

`W`: 화면 드로잉 켜기, `Esc`: 드로잉 닫기. 켜진 동안에는 이동을 포함한 키보드 조작과 휠이 잠긴다. 상단 도구 막대에서 펜 색·두께, 네모, 텍스트, 지우개, 전체 삭제를 고른다. 텍스트 도구를 고른 뒤 원하는 곳을 더블클릭해 입력하고, 바깥을 클릭하면 확정된다. 텍스트 입력창은 내용에 맞춰 가로로 넓어지고 장표 끝에서는 줄바꿈하며, 높이도 자동으로 늘어난다. 닫으면 메모가 화면에서 사라지고, 같은 장표에서 다시 켜면 그대로 나타난다. 스텝을 넘겨도 유지되지만 장표를 앞이나 뒤로 넘기면 메모가 영구 삭제된다. 새로고침하거나 페이지를 닫으면 복원되지 않으며, 로컬 서버 연결이 끊겨도 임시 메모를 지운다. 발표자 창에서 `W`를 눌러도 발표 화면의 드로잉 모드가 같이 켜지며, `Esc`로 닫을 수 있다. 전체화면에서는 `Esc`가 드로잉이나 확대 이미지를 먼저 닫고, 다음 `Esc`가 전체화면을 닫는다.

4·24·35·39·40·57번에는 React Bits 기반 포인터·클릭 연출이 있다. 1번은 원래 표지로 유지한다.
24번 이미지는 클릭하면 크게 열리고 Escape로 닫힌다. 확대 중에도 방향키로 발표를 이어갈 수 있다.
적용 컴포넌트와 조작법은 [인터랙션 기록](../docs/react-bits-performance.md)에 있다.

## 서비스 시연 방식

본편은 **30~32번에 담은 실제 결과물을 장표 진입 시 자동 재생**한다. 30번과 32번은 화면이 나타난 뒤 1초 쉬고 시작한다. `P`는 재생/일시정지,
`A`는 소리 켜기/끄기다. 30번 Bob 데모 영상과 32번 음악은 소리가 켜진 상태로 시작하고 31번 프리비즈는 무음 원본이다.
다음 장으로 이동하면 이전 미디어는 종료된다. 브라우저가 소리 자동 재생을 막으면 장표의 재생 버튼을 누른다.
음악은 `감성 힙합 초안` 3분 WAV(`public/demos/emotional-hiphop-draft.wav`)다.

30~32번 오른쪽 아래의 **TTS / Assets / Music 엔진 실행** 버튼으로 실제 앱을 연다.
32번에는 그 왼쪽에 **뮤직비디오** 링크가 있다. `../mv/render/hiphop-mv-tel.mp4`(git에 넣지 않는 렌더 결과)를 새 탭에서 열고, 이 장의 음원은 멈춘다. 파일이 없으면 링크가 보이지 않는다.
33번 셋째 화면에는 **같은 요청으로 만든 사이트** 링크 셋이 있다(Claude = `../opus-site`, Astra = `../astra-site`, RICE · 로컬 = `../rice-site`, 발표자의 RICE가 로컬 모델로 만든 것). RICE는 이 컴퓨터에 있으면 링크 대신 엔진 버튼과 같은 방식으로 RICE 앱을 띄운다(`demo-launchers/RICE.command`, 이미 켜져 있으면 그 창을 앞으로). 없으면(다른 컴퓨터, 실행 서버 없이 연 덱, 앱 실행 실패) 같은 버튼이 정적 사본 `public/sites/rice-site.html`(보정 1 판)을 새 탭에서 연다. 어느 쪽인지는 장이 열릴 때 `/__javis/engines/rice/available`로 미리 정한다(누른 뒤에 정하면 새 탭이 팝업으로 막힐 수 있다). 대화방 "TEL 홈페이지 · Claude·Astra와 같은 요청 (컨텍스트 64K)"의 파일 저장 카드에서 `tel-site/index.html`을 누르면 사이트가 열린다. RICE 작업 폴더의 그 파일은 보정 1을 반영한 판(`../rice-site/rounds/1-review1.html`)으로 되돌려 두었고, three.js·글꼴을 CDN에서 불러와 인터넷이 필요하다(제작 기록은 `../rice-site/README.md`). 각 사이트를 HTML 파일 하나로 묶어(`npm run build:single`, 결과는 `../out/`) `public/sites/`에 두었고, 링크는 서버 없이 새 탭에서 그 파일을 연다. 사이트를 고쳤다면 다시 묶어서 `public/sites/`에 복사한다. 같은 파일을 팀에 그대로 공유할 수 있다.
16번 7단계 출처 줄의 **젠슨 황의 AI 오리 로봇**과 33번 첫 화면의 **트빌 20Billion**(개그맨 채널의 AI 드라마)은 YouTube 쇼츠를 새 탭에서 연다. 이 둘과 33번 셋째 화면의 RICE 사이트, 40번 셋째 단계의 팬 뮤비 링크만 인터넷이 필요하다.
엔진 실행 버튼과 뮤직비디오 링크는 로컬 발표 서버의 `/__javis/…` 경로(`tools/engine-launcher.mjs`)로 동작한다.
버튼을 누르면 미디어를 일시정지하고 전체화면을 빠져나온 뒤, 터미널에서 해당 엔진 루트의
`./app.sh`를 실행한다. 초기 준비와 실행 로그는 열린 터미널에서 확인한다.
버튼은 macOS의 로컬 발표 서버(`npm run dev` 또는 `npm run preview`)에서 동작한다.
서버 설정을 바꾼 뒤 이미 켜져 있던 서버에는 재시작이 필요하다. 정적 파일만 배포한 화면에는 실행 서버가 없다.
`demo-launchers/TTS.command`, `Assets.command`, `Music.command`를 직접 열어도 같은 앱을 실행한다.

25번부터 →로 진행하면 각 장면의 영상이 한 번 재생되고(장면마다 4초) 마지막 화면에서 멈춘다. 스스로 넘어가지 않는다: 장면마다 말을 할지 바로 넘길지는 발표자가 정한다.
재생되는 동안에는 장면의 이름과 제목이 보이고, 설명 줄은 멈춘 화면에서 나온다.
21→22는 중앙 화면을 통과해 IBM Bob 데모 영상 화면으로 들어가고, 22→23은 화면 프레임을 맞춰 이미지 장면으로 바뀐다.
23→24는 화면을 가로지르는 물체 뒤에서 탑뷰로 전환하고, 24→25는 원반의 중앙을 통과해 전체 결과물을 보여준다.
←는 이전 장면의 마지막 화면을 보여준다. M으로 모션을 끄면 마지막 화면을 바로 표시하고, 다시 켜도 이미 끝난 장면을 재생하지 않는다. R은 현재 영상을 처음부터 재생한다.

Blender 원본 렌더 도구는 `tools/render-factory-film.py`, 배포용 영상과 마지막 화면은 `public/factory-film/`에 있다.
27번에 쓰는 청록색 새는 이 발표를 위해 Local Assets Engine으로 새로 생성한 2D 이미지다.
이미지 원본·프롬프트·모델·시드는 `public/engines/factory-assets/hero.json`에 있다. 기존 출력이나 엔진 코드는 변경하지 않았다.

24번의 미리보기는 실제 IBM Bob 데모 영상 캡처, 새 이미지가 등장하는 장면, 음악 파형 장면이다. Blender 영상의 목소리 화면(25번 갤러리 가운데, 26번 통로 끝, 27번 전환)과 29번 몽타주도 같은 Bob 영상이다(2026-10-26 다시 렌더, 28번 음악 장면은 그대로).
34~41번은 어두운 방과 붉은색(덱의 색 규칙에서 빨강 = 사실이 아님)으로 분위기를 바꾼다(`src/keynote/abuse/`).
37번 두 번째 단계에서 같은 말을 LoRA 강도 0·0.5·1.0으로 만든 목소리가 1초 간격으로 겹치고, 같은 목소리가 3반음 낮고 느리게 "엄마. … 나, 제호 아니야."라고 마지막 말을 한다(Qwen3-TTS + LoRA 0.6, `threshold-final-line.m4a`). 가상 음성 연출이며 38번의 통화 장면은 그대로 유지한다. 음성 아래에 Python으로 합성한 소리를 깐 12.4초 큐(`threshold-scene.m4a`)를 재생한다: 벽이 가라앉는 쿵 소리와 군중의 낮은 압력(0~1.7초) → 겹치는 목소리 아래 단2도·트라이톤 드론이 반음 올라가고 심장 박동이 빨라짐 → 컷과 0.7초 정적(귀울림만) → 고역을 깎은 마지막 말과 어두운 잔향. 원본 음성은 `threshold-voices.m4a` 그대로이고, `python3 tools/render-threshold-sound.py`(기본 strong, `--final-pitch`·`--final-tempo`로 마지막 말 조정)로 다시 만든다. P는 재생·일시정지, A는 음소거다. 제작 기록은 `public/abuse/audio/threshold-voices.json`에 있다.
34번은 장표 진입 뒤 약 1.35초 쉬고 영어 내레이션 샘플을 자동 재생한다. 제공받은 `english-narration-sample.m4a`의
앞 22.5초를 제거해 “First”부터 끝까지 약 59.1초 재생하며, 파형과 영어 문장은 이 샘플에 맞춰 표시한다.
다음 단계에서 "저는 이 문장을 녹음한 적이 없습니다"로 붉게 바꾸고, 제 목소리 어댑터의 실제 학습 기록
(12.3분·35.3초·약 67MB)과 공개 모델의 "3초" 설명을 놓는다. P는 재생·일시정지, A는 소리다.

transparent는 더하기로 그린 빛에 밝기만큼 알파를 채워 다시 쓴다. 그러지 않으면 Safari가 알파 0인 빛을 버려 56번에 라벨만 남는다. 발표는 Chrome으로 하므로 Chromium 검사가 기준이다(2026-10-14).
9~14번은 three.js로 만든 사건 재구성 공간 하나를 여섯 장 동안 유지한다(묶음 incident-rooms).
9번은 8번과 사건 사이의 연결 장면이다. 방 A의 에이전트가 7번의 WebMCP 판을 빛줄기로 부르다가(9-0), 줄이 끊기고 둘레로 유리벽이 올라오며 방화벽이 켜진다(9-1).
→를 누르면 카메라가 물러나고 나머지 방 세 개와 공용 서버가 바닥에서 솟아 10번이 된다. ←로 돌아오면 다시 가라앉는다. 10번부터 →를 누를 때마다 카메라가 이동하며 격리된 실행 4개, 공용 서버, 방화벽, 게시판, 외부 인터넷, Hugging Face 침해를 차례로 보여준다.
13·14번은 같은 공간에서 날짜와 결과만 다룬다(선을 어떻게 넘었는지는 다루지 않는다). 금색은 사람(OpenAI), 호박색은 AI가 넘은 선이다.
13-0에서 방과 서버는 그대로 서 있고, 방화벽 밖 OpenAI 기둥에서 금색 선 하나가 방들 뒤의 과제 판(게시판과 같은 홀로그램) 한가운데에 닿는다("풀어라"). 닿은 곳에서부터 평가 과제 898칸이 켜지고 오른쪽 198칸이 호박색으로 판 앞으로 떠오른다.
13-1에서 과제 판이 물러나고, 방 A에서 호박색 선이 공용 서버(6.26, 서버가 호박색이 된다) → 방화벽 밖 인터넷(7.8, 벽이 출렁인다) → Hugging Face(7.11~13, 파동)로 하나씩 이어진다.
14-0에서 게시판·방 A·서버의 금색 신호 세 개(5.26 · 6.27 · 7.5)가 기둥으로 날아가 고리가 하나씩 켜진다. 그 사이사이 흐려진 호박색 선이 날짜 차례에 다시 빛나고, 다 켜진 뒤 "보는 것과 멈추는 것은 다릅니다"가 나온다.
14-1에서 호박색 선이 꺼지고 방화벽이 금색(범위) → 기둥에서 방마다 금색 선(감시) → 방마다 금색 고리(중단) 순서로 켜진다.
아래 띠의 날짜와 결론은 3D 장면에서 그 일이 일어나는 초에 맞춰 켜진다(`Stories.tsx`의 cue, 라벨은 `IncidentWorld.tsx`의 at).
앞으로 갈 때만 해당 단계의 움직임(연결 시도, 메모 이동, 게시판 재구성, 외부 연결)이 재생되고, ←는 이전 단계의 마지막 상태로 돌아간다. 아래 타임라인은 5월 초기 훈련과 7월 보안 평가를 서로 다른 구간으로 표시한다.
M 또는 모션 줄이기 설정에서는 각 단계의 마지막 상태를 바로 표시한다. WebGL을 쓸 수 없으면 기존 2D 도해(`IncidentDiagram.tsx`)를 표시한다.

## udemy-agent와 차별점

- **장표가 훨씬 적다.** 798장 → 28장. 온라인 얼굴없는 강의는 화면이 말을 다 해야
  해서 장표가 기하급수적으로 늘지만, 이 강의는 사람이 직접 말하는 오프라인이라
  화면은 결론 한 줄만 들고 설명은 화자가 한다.
- **글자가 적다.** 한 화면 1주장+1근거를 더 빡세게 지킨다. 청중은 화면을 읽는 게
  아니라 화자를 보면서 한 귀를 화면에 둔다.
- **애니메이션은 살린다.** 오프라인이라고 정지 장표로 가지 않는다. 스텝 순차공개,
  금색 metric(ShinyText), 가운데 정렬 착지를 전 장에 깔아 화면이 계속 살아 있다.
- **실물은 시연 자리다.** TTS 파이프라인 등은 화면에 결과를 한 줄만 두고 과정은
  현장 시연과 말로 한다.

## bespoke 씬 3종 (`Javis*.tsx` + `javis-scenes.css`)

- **b · `javis-handoff`** (`open-split`·`open-take`, scene `jd-handoff` 공유):
  2008 금색칸 → 2026 칩이 하나씩 파랑으로 넘어가고 AGENT 스탬프.
- **a · `javis-token`** (`token-ticker`): 900×·31%·+2,434% 카운트업 티커 + 착지.
- **c · `javis-loop`** (`factory-loop`, scene `jd-loop`): 의도→판단→생산→검증
  순환도. 흐르는 파선 + 도는 점 + 스텝별 노드 점등.
- 신규 레이아웃은 `course-types.ts` union과 `tools/course-terms.js`의
  `STEP_AWARE_LAYOUTS`에도 등록돼 있어 lint 오탐이 나지 않는다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5180 — #course 로 28장 연속 확인
```

슬라이드 이동: `→`/`Space` 스텝 진행, 숫자+`Enter` 점프, `H` 조작 바,
`F` 전체화면, `Esc` 종료, `S` 자막 안전영역.

## 검증

```bash
npm run typecheck
npm run lint:offline   # 오프라인 기준(리듬 한도 3배). 온라인 잣대는 lint:course
npm run where -- token-ticker
```

화면 ID는 내용 기반 슬러그이며 위치를 담지 않는다. 화면과 대본은
ID로 묶이고, 어긋나면 개발 서버가 경고한다.
