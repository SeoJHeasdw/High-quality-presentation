# Technology Expert Lab — RICE가 만든 사이트

`opus-site/`(Claude), `astra-site/`(Astra)와 같은 요청을 발표자의 업무 에이전트 RICE에게 넣어 만든 사이트다. RICE는 로컬 모델(Ollama `qwen3.6:35b-a3b-q4_K_M`)로 돌아서 API 비용이 들지 않는다. 덱 32번 셋째 화면의 "RICE · 로컬" 버튼은 RICE가 있는 컴퓨터에서는 RICE 앱을 띄우고, 발표자가 대화방의 파일 저장 카드에서 `tel-site/index.html`을 눌러 연다. RICE가 없는 컴퓨터에서는 정적 사본 `deck/public/sites/rice-site.html`(같은 보정 1 판)을 연다. RICE 작업 폴더(`~/.rice/workspace/tel-site/index.html`)의 그 파일은 최종본이 아니라 `rounds/1-review1.html`(보정 1까지, 약 21분)로 되돌려 두었다(2026-10-26). 최종본은 마지막 보정에서 첫 화면을 짙은 막으로 덮어 3D가 보이지 않아서, 3D가 가장 잘 보인 판을 발표자가 골랐다(2026-10-26). 이 판의 글에는 "dozen", "品質管理体系", "地上"이 섞여 있다.

`index.html`(최종본)과 `rounds/`의 파일은 모두 RICE가 쓴 그대로이며 사람이 고친 곳이 없다. three.js r128(cdnjs)과 Google Fonts를 CDN으로 불러오므로 **인터넷이 필요하다**.

## 조건 (2026-10-26)

- 요청: 아래 원문 그대로, 새 대화에서 한 번. Claude·Astra와 달리 13번 장표 참고 화면은 주지 않았다(글 요청만).
- 보정: Claude·Astra와 같이 최대 3번. 보정은 눈에 보이는 문제만 말하고 고치는 방법은 알려주지 않았다.
- 실행: RICE 런타임 API(`approve_for_me`). 셸 명령 승인은 작업 폴더 안의 읽기·만들기만 허용했고, 실제로 요청된 것은 `mkdir -p tel-site` 한 번이다.
- 설정: 기본 컨텍스트 32K에서는 로컬 출력 한도(컨텍스트의 1/4 = 8,192토큰)에 걸려 두 번 모두 빈 파일로 끝났다. 결과물이 없어 보정으로 세지 않고, 앱 설정에서 바꾸듯 `num_ctx`만 64K(출력 16K)로 올려 새 대화에서 다시 시작했다. 끝난 뒤 32K로 되돌렸다.

요청 원문:

> 고급 건설사 'Technology Expert Lab'의 홈페이지를 만들어줘. 시간이 오래 걸려도 괜찮으니 디자인 감각, 홈페이지 제작 기법, 3D 스크롤 이벤트를 총동원해서 네가 만들 수 있는 최고 수준으로 만들어줘. 결과는 작업 폴더의 tel-site/index.html 파일 하나로 저장해줘(CSS와 JS는 파일 안에 넣고, 필요하면 three.js 같은 라이브러리는 CDN으로 불러와도 돼). 중간에 나한테 묻지 말고 끝까지 진행하고, 다 만들면 파일을 다시 읽어서 빠진 부분이나 오류가 없는지 확인해줘.
